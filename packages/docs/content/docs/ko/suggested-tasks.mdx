# 제안된 작업

제안된 작업은 프로젝트를 읽고 할 일을 제안하는 스캔입니다. 잊힌 TODO, 보안 구멍, 코드와 맞지 않게 된 문서 같은 것들입니다. 제안은 각각 받은편지함에 도착하고, 거기서 세션을 시작하거나, 할 일이나 이슈로 바꾸거나, 미루거나, 닫을 수 있습니다. 받은편지함은 세션 사이드바 상단의 전구 아이콘으로 엽니다. 전구에 점이 있으면 열린 제안이 있다는 뜻입니다.

스캔은 파일을 읽기만 합니다. 파일을 편집하거나, 명령을 실행하거나, MCP 도구를 사용할 수 없습니다. 작업은 제안을 승인하거나 렌즈가 스스로 동작하도록 설정했을 때만 시작됩니다.

## 프로젝트에서 켜기

1. **설정 → 프로젝트**를 열고 프로젝트를 선택한 다음 **제안된 작업** 탭을 엽니다.
2. **제안된 작업을 위해 이 프로젝트 스캔**을 체크합니다.
3. **렌즈**에서 **렌즈 추가**를 클릭하고 **보안**이나 **잊힌 TODO 및 FIXME** 같은 시작점을 고릅니다. 원하면 두 번째 렌즈도 추가하세요.
4. **스캔 시점**을 선택합니다. **수동**은 직접 시작할 때만 스캔을 실행합니다.
5. **지금 스캔**을 클릭합니다.

받은편지함에 스캔이 실행 중으로 표시됩니다. 각 렌즈는 끝나는 대로 제안을 추가하며, 보통 몇 분 안에 끝납니다.

## 렌즈

렌즈는 한 종류의 작업을 찾습니다. 각 렌즈에는 다음이 있습니다.

- 이름과, 무엇을 찾을지 알려 주는 프롬프트
- 자체 모델, 사고 수준, 에이전트 또는 프로젝트의 세션 기본값
- 웹 액세스. 허용하지 않으면 꺼져 있으며, 의존성 렌즈는 최신 버전을 확인하는 데 사용합니다
- 찾은 결과를 어떻게 처리할지

시작점은 잊힌 TODO 및 FIXME, 보안, 성능, 접근성, 테스트 커버리지, 오래된 의존성, 오래된 문서, 죽은 코드입니다. 각 시작점은 프롬프트를 렌즈에 복사하므로 수정할 수 있습니다. **사용자 지정 렌즈**는 빈 상태로 시작합니다.

스캔의 각 렌즈는 자기 세션에서 실행됩니다. 하나가 실패해도 나머지는 제안을 추가하며, 받은편지함에 어느 렌즈가 왜 실패했는지 표시됩니다. 렌즈 옆의 재생 버튼을 클릭하면 그 렌즈만으로 스캔합니다.

### 렌즈가 제안을 처리하는 방식

기본적으로 렌즈는 제안만 합니다. 모든 제안이 받은편지함에서 기다립니다. 스스로 동작하게 할 수도 있습니다.

| 선택 | 새 제안마다 일어나는 일 |
|---|---|
| 제안만 | 받은편지함에서 대기합니다. |
| 프로젝트 할 일에 추가 | [프로젝트 메모, 할 일, 계획](/ko/notes-todos-plans/)의 할 일이 됩니다. |
| 세션 시작 | 프로젝트의 세션이 그 작업을 시작합니다. |
| 새 워크트리에서 세션 시작 | 전용 [worktree](/ko/worktrees/)와 세션이 만들어집니다. |
| 드래프트 PR까지 작업 | worktree 세션이 [목표](/ko/session-goals/)로 작업하고 드래프트 PR를 엽니다. |

마지막 세 가지는 묻지 않고 세션을 시작하며, 그 세션은 토큰을 사용합니다.

## 스캔이 실행되는 때

- **수동**: **지금 스캔**을 클릭할 때만
- **매일** 또는 **매주**: 선택한 시간과 시간대에
- **Cron 일정**: 평일 9:00을 뜻하는 `0 9 * * 1-5` 같은 모든 cron 표현식

**방해 금지 시간**은 22:00부터 07:00 같은 시간대에 걸리는 예약 스캔을 건너뜁니다. 직접 시작한 스캔은 항상 실행됩니다. 스캔 시각은 [예약 작업](/ko/scheduled-tasks/)과 같은 스케줄러가 관리하므로, 창을 닫아도 OpenChamber 서버가 실행 중이면 스캔이 실행됩니다.

## 스캔이 보는 대상

- **이 파일만**과 **이 파일 건너뛰기**는 `src/**`나 `*.test.ts`처럼 한 줄에 패턴 하나를 받습니다.
- **브랜치**는 다른 브랜치를 임시 사본에서 스캔하고, 끝나면 사본을 삭제합니다. 비워 두면 프로젝트 폴더를 있는 그대로 스캔합니다.
- **마지막 스캔 이후 변경된 파일만 확인**를 켜면 이후 스캔은 바뀐 부분만 읽습니다. 범위 안에 바뀐 것이 없으면 스캔을 건너뛰고 비용이 들지 않습니다.

## 한도

- **스캔당 제안 수**는 한 번의 스캔에서 모든 렌즈가 추가할 수 있는 수를 제한합니다. 가장 심각하고 가장 확실한 제안이 남습니다.
- **토큰 예산이 소진되면 스캔 중지**는 스캔이 그만큼의 토큰을 쓰면 아직 읽고 있는 모든 렌즈를 중지합니다.
- **최소 확신도**와 **최소 심각도**는 그 아래의 제안을 제외합니다.

## 받은편지함

각 제안에는 제목, 중요한 이유, 관련된 파일과 줄, 찾아낸 렌즈, 심각도, 렌즈의 확신 정도가 표시됩니다. 파일을 클릭하면 해당 줄에서 열립니다.

- **세션 시작**은 제안을 프롬프트로 삼아 프로젝트에서 세션을 시작합니다.
- **승인 방식**은 더 다양한 진행 방법을 제공합니다.
  - 새 worktree의 세션
  - 드래프트 PR까지 작업하는 worktree 세션
  - 먼저 편집하는 새 초안. 여기서 격리된 공간도 고를 수 있습니다
  - 프로젝트 할 일
  - GitHub, GitLab 또는 Linear의 이슈
- **미루기**는 하루, 일주일, 한 달 동안 숨깁니다.
- **거절**는 선택 사항인 사유를 묻습니다.

이슈를 만들면 제목과 설명이 채워진 상태로 트래커의 새 이슈 페이지가 열립니다. 제출은 본인 계정으로 합니다.

## 원하지 않는 것을 스캔에 알려 주기

스캔은 찾은 내용을 이미 열려 있거나, 미뤄졌거나, 승인된 제안과 비교해 비슷한 것은 제외합니다. 프로젝트에 연결된 GitHub 또는 GitLab 저장소와 매핑된 Linear 팀의 열린 Issue와도 비교합니다. 제공자에 오류가 나거나 백로그가 10페이지를 넘으면 스캔에 경고가 표시됩니다. 유사도 비교는 표현이 다른 중복을 놓칠 수 있습니다. 기본적으로 거절한 제안과 그 사유, 열려 있는 프로젝트 할 일도 읽기 때문에, 한 제안에 "이 위험은 감수한다"고 남기면 비슷한 제안이 줄어듭니다. 둘 다 **중복 방지**에서 끌 수 있습니다.

## 저장소의 렌즈

팀은 `.agents/lenses/`에 markdown 파일로 렌즈를 공유할 수 있습니다.

```markdown
---
name: Security review
model: anthropic/claude-sonnet-4-5
variant: high
agent: plan
web: false
action: suggest
---
Look for injection, missing authorization checks and secrets in logs.
```

필수 항목은 `name`과 본문뿐입니다. `model`이 없으면 렌즈는 세션 기본값을 사용합니다. `action`은 `suggest`, `todo`, `session`, `worktree`, `draft-pr` 중 하나입니다.

저장소의 렌즈는 렌즈 목록에 나타나지만, 내 컴퓨터에서 체크해야 실행됩니다. 나중에 누군가 파일을 바꾸면, 다시 체크할 때까지 대기합니다.

## 알림과 스캔 세션

스캔이 제안을 추가하면 OpenChamber가 [알림](/ko/notifications/)을 보냅니다. **스캔 후**에서 끄면 알리지 않습니다. 스캔 세션은 스캔이 끝나면 보관되어 사이드바에 나타나지 않습니다. 받은편지함의 **마지막 스캔**에서 열 수 있습니다.

## 사용 가능한 환경

받은편지함과 스캔은 웹 앱과 데스크톱 앱에서 동작합니다. 휴대폰에서는 받은편지함을 열고, 스캔을 시작하고, 제안을 처리할 수 있습니다. 설정은 컴퓨터에서 하세요. VS Code 확장은 제안된 작업을 제공하지 않습니다.
