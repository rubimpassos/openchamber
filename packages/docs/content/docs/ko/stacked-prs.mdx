# 스택된 풀 리퀘스트

스택은 각 PR이 아래 PR 위에 쌓이는 풀 리퀘스트 체인입니다. 두 번째 PR의 베이스 브랜치는 첫 번째 PR의 브랜치이고, 이런 식으로 이어집니다. 큰 변경을 이렇게 나누면 각 PR을 리뷰하기 적당한 크기로 유지할 수 있습니다. OpenChamber는 스택에 속한 PR이 나타나는 모든 곳에서 스택 전체를 보여 주고, 체인의 순서를 유지하도록 돕습니다.

스택은 GitHub에서 동작합니다. GitHub가 스택 자체를 알고 있으면(네이티브 스택된 풀 리퀘스트) OpenChamber는 GitHub의 스택을 읽습니다. 그렇지 않으면 PR의 베이스 브랜치에서 체인을 찾으며, 포크와 GitHub Enterprise Server도 여기에 포함됩니다.

## 스택 보기

스택에 속한 풀 리퀘스트를 [이슈 및 PR](/ko/issues-and-prs/) 보드, 풀 리퀘스트 보기 또는 **Git** 보기에서 엽니다. 미리보기에는 모든 PR을 아래에서 위로 나열하는 **Pull request stack** 섹션이 있습니다. 각 행에는 PR의 상태, 체크, 충돌 여부가 표시되고 지금 보고 있는 PR에 표시가 붙습니다. 읽을 수 없는 행은 색을 보여 주는 대신 그렇다고 알려 줍니다.

보드 목록에서 스택된 PR에는 스택 안의 위치를 나타내는 작은 배지(예: **2/3**)가 붙습니다. 스택의 행을 클릭하면 해당 PR이 열립니다.

행에 경고가 표시될 수도 있습니다.

- **Behind base by N commits**: 아래 PR이 바뀌었으므로 이 PR은 restack이 필요합니다.
- **Base was merged. Retarget to main.**: 아래 PR이 병합되었는데 이 PR은 여전히 이전 브랜치를 가리킵니다.
- **Still carries the commits of merged #N**: 아래 PR이 squash로 트렁크에 병합되었는데 이 PR에는 그 이전 커밋이 아직 남아 있습니다.

## 다른 PR 위에 PR 열기

1. 맨 위 PR의 브랜치를 시작점으로 삼아 새 PR용 브랜치를 체크아웃합니다.
2. 스택 섹션에서 **Open stacked PR on top**을 클릭하거나, **Git** 보기의 생성 폼에서 맨 위 PR의 브랜치를 베이스로 선택합니다.
3. 폼에 **Stacked on #N**이 표시됩니다. 제목과 설명을 작성하고 PR을 만듭니다.

GitHub.com에서는 OpenChamber가 새 PR을 GitHub 자체 스택에도 등록합니다. GitHub가 거부해도(포크, 오래된 서버) PR은 그대로 만들어지고 스택도 계속 표시됩니다.

## 아래 변경 후 restack

스택 아래쪽 PR에 새 커밋이 생기면 그 위의 PR은 최신이 아니게 됩니다. **Fetch and restack**을 클릭하세요. OpenChamber는 원격을 fetch하고, 각 브랜치를 아래 브랜치 위로 순서대로 리베이스한 다음, 움직인 브랜치를 push합니다. 그 사이 다른 사람이 브랜치에 push했다면 push가 거부되므로 작업이 덮어써지지 않습니다.

각 브랜치 자신의 커밋만 이동합니다. 아래에서 squash 병합이 일어난 뒤에는 병합된 PR의 이전 커밋이 제외됩니다.

### restack 중 충돌이 생길 때

restack은 충돌이 난 PR에서 멈춥니다. 그 아래 브랜치는 restack된 상태로 남고, 위 브랜치는 기다립니다. 이후 동작은 **Settings → Integrations → GitHub → Restack conflicts**에 따라 달라집니다.

- **Pause and let me choose**(기본값): 스택 섹션이 알려 주는 폴더에서 충돌을 해결하고, 파일을 스테이징한 다음 **Continue**를 클릭합니다. **Abort**는 그 브랜치를 원래대로 되돌리고 나머지를 건너뜁니다. **Ask the session to resolve**는 충돌을 현재 세션에 넘깁니다.
- **Let the session resolve it**: 충돌이 곧바로 세션으로 넘어갑니다. 세션의 턴이 해결되지 않은 것 없이 끝나면 restack이 저절로 이어집니다.

## 스택 병합

아래에서부터 병합하세요. 스택 섹션은 가장 아래의 열린 PR에만 **Merge bottom PR #N**을 제공하며, 평소 쓰는 병합 방식을 사용합니다. 병합된 뒤 다음 PR이 트렁크로 옮겨지고, **Fetch and restack**으로 병합된 커밋이 제거됩니다. 그런 다음 다음 PR을 병합합니다.

## 세션에서 스택 전체 다루기

- 스택 섹션의 **Attach whole stack**은 각 PR의 diff, 체크, 댓글을 순서와 브랜치 요약과 함께 메시지 입력란에 첨부합니다. 한 PR을 읽을 수 없어도 나머지는 첨부되고, 어느 것이 실패했는지 알려 줍니다.
- 세션의 **Linked** 목록에서 연결된 PR의 **Follow whole stack**을 켭니다. 그러면 세션이 스택의 변화를 따라갑니다. 위에 추가된 새 PR, 병합, 대상 변경이 다시 연결하지 않아도 반영됩니다.

## 지원 환경

스택은 웹 앱, 데스크톱 앱, 모바일 앱에서 동작합니다. VS Code 확장은 스택을 표시하지 않습니다.
