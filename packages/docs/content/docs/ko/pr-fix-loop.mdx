# PR 수정 루프

수정 루프는 풀 리퀘스트 하나가 병합 준비를 마칠 때까지 세션이 그 작업을 계속하게 합니다. OpenChamber는 PR의 체크와 리뷰를 지켜봅니다. CI가 실패하면 세션은 실패한 체크를 단계, 주석, 로그 줄과 함께 받습니다. 누군가 리뷰하거나 댓글을 달면 세션은 그 피드백을 받아 변경하고 PR에 답글을 답니다. 루프는 OpenChamber 서버에서 실행되므로 앱을 닫아도 계속됩니다.

PR이 준비되면(CI가 통과하고, 해결되지 않은 리뷰 스레드가 없고, 변경 요청을 기다리는 사람도 없을 때) 루프는 PR을 계속 지켜봅니다. 나중에 생기는 CI 실패나 리뷰도 같은 방식으로 세션에 전달되며, PR이 병합되거나 닫히거나 루프를 중지할 때까지 이어집니다. PR이 준비될 때마다, 그리고 루프가 다른 이유로 멈출 때 알림을 받습니다. **Keep watching after the PR is ready**를 끄면 PR이 준비되는 즉시 루프가 끝납니다.

## 루프 시작

1. 작업을 맡길 세션을 엽니다.
2. [이슈 및 PR](/ko/issues-and-prs/) 보드, 풀 리퀘스트 보기 또는 세션의 **Context sources**(PR 행의 **⋮** 메뉴)에서 풀 리퀘스트를 찾아 **Start fix loop**를 선택합니다.
3. 대화상자의 설정을 확인하고 **Start fix loop**를 클릭합니다.

루프는 세션 메시지 입력란 위쪽에 표시됩니다. PR, 루프가 하는 일, 반복 횟수, CI 상태를 볼 수 있습니다. PR이 준비된 동안에는 **PR ready · watching for new CI and reviews**라고 표시됩니다. 여기서 설정을 바꾸거나, 보드에서 PR을 열거나, **Stop**으로 멈출 수 있습니다.

## 세션이 받는 것

- **push 후**에는 루프가 새 커밋의 CI를 기다립니다. 실패하면 세션은 실패한 체크를 커밋당 한 번만 받으며, 같은 실패를 두 번 받지 않습니다.
- 설정에 따라 포함되는 **리뷰, 리뷰 댓글, 새 댓글마다** 세션은 그 본문과 링크를 받습니다. 세션은 PR에 답글을 달고 해결한 스레드를 닫도록 요청받습니다. 답글을 달고 스레드를 해결하려면 세션에 인증된 자체 GitHub 도구가 있어야 합니다. 루프의 계정은 PR을 읽는 데만 쓰입니다.

채팅에서는 이 메시지 하나하나가 접힌 한 줄로 표시됩니다. 예를 들어 **Fix loop: CI failed on #5**나 **Fix loop: new review on #6**처럼 커밋, 작성자, 반복 횟수가 함께 나옵니다. 열면 세션이 받은 내용을 전부 읽을 수 있습니다. 실패한 체크, 단계, 주석, 로그 줄, 또는 리뷰 본문과 작성자, 링크입니다. 사용자가 입력한 메시지로 표시되는 일은 없습니다.

세션이 바쁘면 메시지는 대기열에서 기다렸다가 턴이 끝날 때 전달됩니다. 대기 중인 수정 루프 메시지는 삭제할 수 있지만 앱에서 편집하거나 보낼 수는 없으며, 전송된 뒤에도 같은 줄이 남습니다. GitHub에 연결할 수 없으면 루프는 알고 있던 상태를 유지하고 확인하지 못했다고 알립니다. 실패한 체크를 통과로 읽는 일은 없습니다.

## 설정

기본값은 **Settings → Integrations → GitHub → Fix loop**에 있으며, 각 루프에서 바꿀 수 있습니다.

- **Keep watching after the PR is ready**: 기본값은 켜짐입니다. 끄면 PR이 준비되는 즉시 루프가 끝납니다.
- **Maximum iterations**: PR이 다시 준비될 때까지 루프가 세션에 작업을 보낼 수 있는 횟수(기본값 10). PR이 준비될 때마다 횟수를 처음부터 다시 셉니다.
- **Token budget**: 루프가 시작된 뒤 세션이 모든 라운드를 합쳐 이 만큼의 토큰을 쓰면 멈춥니다. 비워 두면 예산이 없습니다. 예산은 매 턴이 끝난 뒤 확인하므로 한 턴 안에서 초과할 수 있습니다.
- **Respond to**: **CI and reviews**, **CI only**, **Reviews only**.
- **Ignore my feedback**: 루프가 PR을 읽는 데 쓰는 GitHub 계정의 댓글을 건너뜁니다. 기본값은 꺼짐이라서 에이전트의 PR을 본인 계정으로 리뷰할 수 있고, 세션은 모든 스레드를 받습니다. 에이전트 자신의 답글은 마커로 건너뜁니다(아래 참고).
- **Ignore bots**: 봇의 댓글을 건너뜁니다.
- **Allowed authors**와 **Blocked authors**: 쉼표로 구분한 GitHub 로그인. 허용 목록이 있으면 그 사람들만 포함됩니다.
- **Only comments that mention this text**: 멘션 텍스트(기본값 `@openchamber`)가 들어 있는 댓글만 포함합니다.
- **Push changes**: **Push automatically** 또는 **Wait for my approval**. 자동 모드는 세션 자체의 GitHub 워크플로를 그대로 씁니다. 승인 모드는 수정을 제한된 워커에서 실행하며 별도 설정이 필요합니다.

## 에이전트가 GitHub에 쓰는 텍스트

에이전트가 쓰는 모든 댓글, 답글, 리뷰는 짧은 한 줄 **Written by the OpenChamber agent**와 숨겨진 마커(`<!-- openchamber-agent:v1 -->`)로 끝납니다. 루프는 작성자 설정과 상관없이 마커가 있는 텍스트를 항상 건너뜁니다. 그래서 사용자와 에이전트가 같은 GitHub 계정을 쓰더라도 에이전트의 답글이 새 피드백으로 되돌아오지 않습니다. 승인 모드에서는 서버가 게시하는 답글에 마커를 붙입니다. 자동 모드에서는 세션에 마커를 붙이라고 지시합니다. 세션이 잊어버린 경우에도, 읽기 계정이 세션의 턴이 도는 동안이나 턴이 끝나고 2분 안에 게시한 답글은 루프가 건너뜁니다.

마커는 텍스트에 붙이는 라벨이며 서명이 아닙니다. 누구나 댓글에 붙여 넣어 그 댓글에 루프가 반응하지 않게 할 수 있습니다. 막는 것은 반응뿐이며, 접근 권한을 주지 않고 작업도 시작하지 않습니다.

## 승인 모드

**Wait for my approval**에서는 세션이 push하지 않습니다. 제한된 워커가 격리된 스페이스에서 PR을 고치고, 정확한 커밋을 승인하기 전에는 GitHub에 어떤 변경도 게시되지 않습니다. 루프가 도는 동안에도 서버는 GitHub에서 PR을 계속 읽습니다.

### 워커 설정

1. 격리 스페이스를 켜고 위치를 설정합니다. 수정 루프가 이를 대신 켜는 일은 없습니다.
2. 시작 대화상자에서 **Restricted worker**를 찾습니다. 워커가 실행될 위치와 모델을 고르고 **Prepare new worker**를 클릭합니다. 이 워커만 쓰는 새 스페이스가 만들어집니다. 기존 스페이스는 재사용하거나 변환할 수 없습니다.
3. 접근 대화상자에서 워커의 모델에 접근 권한을 줍니다. 선택한 모델에만 권한이 갑니다. 모델 토큰은 게이트키퍼가 보관하고 워커는 볼 수 없습니다. 모델 사용량은 내 쿼터에서 차감됩니다.
4. PR의 head 저장소는 포크를 포함해 그 저장소 전용의 관리되는 Git push 대상이 필요합니다. 없으면 대화상자가 Git 설정으로 안내합니다.
5. 워커가 준비되었다고 표시되면 **Start fix loop**를 클릭합니다.

워커는 모델 외에 GitHub나 다른 네트워크에 접근할 수 없습니다. 시스템이나 환경의 push로 대체되는 경로도 없습니다. 워커가 준비되지 않았거나 접근 권한이 없으면 루프가 시작되지 않습니다. 제한된 워커용으로 검토되지 않은 모델이나 사용자 지정 엔드포인트는 거부되며, 다른 것으로 바뀌지 않습니다.

**Forget worker selection**은 선택만 지웁니다. 스페이스와 파일은 남고 격리 스페이스에서 관리합니다.

### 검토하고 게시하기

턴이 끝나면 서버가 워커의 커밋을 내보내 정확한 저장소, 브랜치, 예상 원격 head와 함께 영수증으로 보관합니다. 그러면 루프에 **Review publication**이 나타납니다. **Inspect exact changes**를 열어 확인하고 **Approve and publish commit**을 클릭합니다. 일반 Git push 버튼은 영수증을 승인하지 않습니다. PR이 닫혔거나 원격 head, 브랜치, 저장소가 바뀌면 게시가 거부되고, 영수증과 작업은 확인할 수 있게 남습니다.

### 게시 후 답글

검토 대화상자의 **Automatic GitHub replies**에는 생성된 답글과 해결될 스레드가 나열됩니다. 워커가 쓴 글이므로 승인하기 전에 인용된 텍스트를 읽어 보세요. 커밋이 게시되면 서버가 워커와 무관한 자체 GitHub 쓰기 권한으로 답글을 달고 스레드를 해결합니다. 모든 클라이언트가 닫혀 있어도 진행됩니다. 쓰기가 실패하면 루프가 이를 표시하고 PR을 ready로 보고하지 않습니다.

### 중지, 재개, 예산

**Stop**은 워커를 멈추고 코드와 영수증을 남깁니다. **Resume fix loop**는 워커를 다시 확인해 시작하며, 중지된 루프의 영수증은 그 뒤에야 게시할 수 있습니다. 끝난 루프를 잊어도 그 스페이스는 삭제되지 않습니다.

실행 모드는 루프마다 고정입니다. 대기 중인 게시와 GitHub 답글을 완료한 뒤 루프를 중지하고 다른 모드를 시작하세요. 영수증이나 GitHub 답글이 대기 중일 때는 설정도 잠깁니다.

토큰 예산은 각 턴이 끝난 뒤 확인하므로 한 턴이 예산을 넘을 수 있습니다. 예산에 도달하면 새 모델 턴은 시작되지 않지만, 대기 중인 내보내기, 게시, 답글은 끝낼 수 있습니다. 그다음 루프에 토큰 예산 상태가 표시됩니다.

### 승인 모드를 쓸 수 있는 곳

서버는 모든 클라이언트가 닫혀 있어도 루프를 실행합니다. 웹 앱, 데스크톱 앱, 모바일 앱이 이 서버를 공유합니다. VS Code 확장은 승인 모드를 제공하지 않습니다.

## 루프가 멈추는 경우

| 상태 | 이유 |
| --- | --- |
| PR 준비 완료 | CI 통과, 해결되지 않은 스레드 없음, 요청된 변경 없음, 그리고 **Keep watching after the PR is ready**가 꺼져 있음 |
| PR 닫힘 | PR이 병합되었거나 닫힘 |
| 반복 한도 | 루프가 허용된 횟수만큼 작업을 보냄 |
| 토큰 예산 | 세션이 예산을 모두 사용함 |
| 중지됨 | 사용자가 중지했거나 세션이 삭제됨 |

멈춘 루프는 닫을 때까지 메시지 입력란 위에 남아 있습니다. 지켜보기 기능이 생기기 전에 준비 완료로 끝난 루프는 끝난 상태로 남습니다. PR을 지켜보려면 닫고 다시 시작하세요. 승인 모드에서 영수증이나 GitHub 답글이 대기 중이면 작업은 보존되고 루프도 남으므로, **Resume fix loop**로 기존 루프를 이어갑니다. 같은 PR에서 새 루프를 시작할 수 있는 것은 대기 중인 게시나 답글이 없을 때뿐입니다.

## 스택

각 풀 리퀘스트에는 자체 루프가 있습니다. [스택](/ko/stacked-prs/)에서는 수정하려는 PR마다 루프를 시작하세요. 한 PR의 실패가 다른 PR을 막지 않습니다.

## 지원 환경

루프는 웹 앱, 데스크톱 앱, 모바일 앱 뒤의 OpenChamber 서버에서 실행됩니다. VS Code 확장에서는 제공되지 않습니다.
