# タスクの提案

タスクの提案は、プロジェクトを読んで作業を提案するスキャンです。忘れられた TODO、セキュリティの穴、コードと合わなくなったドキュメントなどが対象です。提案はそれぞれ受信トレイに届き、そこからセッションを開始したり、Todo や Issue に変えたり、スヌーズしたり、却下したりできます。受信トレイはセッションサイドバー上部の電球から開きます。電球に点が付いていれば、未処理の提案があります。

スキャンはファイルを読むだけです。編集もコマンド実行も、MCP ツールの利用もできません。作業が始まるのは、提案を承認したときか、レンズに自動で動くよう設定したときだけです。

## プロジェクトで有効にする

1. **設定 → プロジェクト**を開き、プロジェクトを選んで**タスクの提案**タブを開きます。
2. **このプロジェクトをスキャンしてタスクを提案する**にチェックを入れます。
3. **レンズ**の下で**レンズを追加**をクリックし、**セキュリティ**や**忘れられたTODOとFIXME**などの出発点を選びます。2つ目を追加してもかまいません。
4. **スキャンのタイミング**を選びます。**手動**は、自分で開始したときだけスキャンを実行します。
5. **今すぐスキャン**をクリックします。

受信トレイにはスキャンが実行中と表示されます。各レンズは終わった時点で提案を追加します。通常は数分以内です。

## レンズ

レンズは1種類の作業を探します。各レンズには次の設定があります。

- 名前と、何を探すかを指示するプロンプト
- 独自のモデル、思考レベル、エージェント。またはプロジェクトのセッション既定値
- Web アクセス。許可しない限りオフです。依存関係のレンズは、現在のバージョンの確認に使います
- 見つけたものをどう扱うか

出発点は、忘れられたTODOとFIXME、セキュリティ、パフォーマンス、アクセシビリティ、テストカバレッジ、古い依存関係、古いドキュメント、デッドコードです。どれもプロンプトがレンズにコピーされるので、変更できます。**カスタムレンズ**は空の状態から始まります。

スキャンの各レンズは、それぞれ別のセッションで動きます。1つが失敗しても、ほかのレンズは提案を追加し、受信トレイにどのレンズがなぜ失敗したかが表示されます。レンズの横の再生ボタンをクリックすると、そのレンズだけでスキャンします。

### レンズが提案をどう扱うか

既定では、レンズは提案するだけです。すべて受信トレイで待機します。自動で動かすこともできます。

| 選択 | 新しい提案ごとの動作 |
|---|---|
| 提案のみ | 受信トレイで待機します。 |
| プロジェクトのTodoに追加 | [プロジェクトのメモ、Todo、計画](/ja/notes-todos-plans/)の Todo になります。 |
| セッションを開始 | プロジェクトのセッションがその作業を始めます。 |
| 新しいワークツリーでセッションを開始 | 専用の [worktree](/ja/worktrees/) とセッションが作られます。 |
| ドラフトPRまで作業 | worktree セッションが[ゴール](/ja/session-goals/)として作業し、ドラフトPRを開きます。 |

最後の3つは確認なしでセッションを開始し、そのセッションはトークンを消費します。

## スキャンの実行タイミング

- **手動**: **今すぐスキャン**をクリックしたときだけ
- **毎日**または**毎週**: 選んだ時刻とタイムゾーンで
- **Cronスケジュール**: 平日の9:00なら `0 9 * * 1-5` のような任意の cron 式

**静音時間**は、22:00 から 07:00 のような時間帯に当たる予定スキャンをスキップします。自分で開始したスキャンは常に実行されます。実行タイミングは[スケジュールタスク](/ja/scheduled-tasks/)と同じスケジューラーが管理するので、ウィンドウを閉じていても OpenChamber のサーバーが動いている間はスキャンが実行されます。

## スキャンが見る範囲

- **これらのファイルのみ**と**これらのファイルを除外**は、`src/**` や `*.test.ts` のようなパターンを1行に1つ入力します。
- **ブランチ**は、別のブランチを一時コピーでスキャンし、終わると削除します。空欄ならプロジェクトフォルダーをそのままスキャンします。
- **前回のスキャン以降に変更されたファイルのみ確認**を有効にすると、以降のスキャンは変更分だけを読みます。対象範囲に変更がなければスキャンはスキップされ、費用はかかりません。

## 上限

- **1回のスキャンあたりの提案数**は、1回のスキャンですべてのレンズが追加する数を制限します。深刻度が高く確度の高いものが残ります。
- **トークン予算でスキャンを停止**は、スキャンがその数のトークンを使った時点で、まだ読んでいるすべてのレンズを停止します。
- **最低確度**と**最低重大度**は、それを下回る提案を除外します。

## 受信トレイ

各提案には、タイトル、重要な理由、関係するファイルと行、見つけたレンズ、深刻度、レンズの確信度が表示されます。ファイルをクリックすると、その行で開きます。

- **セッションを開始**は、提案をプロンプトにしてプロジェクトでセッションを開始します。
- **承認方法**では、ほかの進め方を選べます。
  - 新しいワークツリーでのセッション
  - ドラフトPRまで作業する worktree セッション
  - 先に編集する新しいドラフト。ここでは分離スペースも選べます
  - プロジェクトの Todo
  - GitHub、GitLab、Linear の Issue
- **スヌーズ**は、1日、1週間、1か月のあいだ非表示にします。
- **却下**では、任意で理由を入力できます。

Issue を作成すると、タイトルと説明が入力された状態でトラッカーの新規 Issue ページが開きます。送信は自分のアカウントで行います。

## 不要なものをスキャンに教える

スキャンは、見つけた内容を未処理、スヌーズ中、承認済みの提案と比較し、似たものは除外します。プロジェクトに紐づく GitHub または GitLab リポジトリと、割り当て済みの Linear チームにある未解決の Issue とも比較します。プロバイダーでエラーが起きた場合や、バックログが10ページを超える場合は、スキャンに警告が表示されます。類似度による照合では、言い回しが違う重複を見逃すことがあります。既定では、却下した提案とその理由、未完了のプロジェクト Todo も読みます。そのため、ある提案に「このリスクは受け入れる」と書けば、似た提案は出にくくなります。どちらも**重複を避ける**でオフにできます。

## リポジトリ内のレンズ

チームは、`.agents/lenses/` に markdown ファイルとしてレンズを共有できます。

```markdown
---
name: Security review
model: anthropic/claude-sonnet-4-5
variant: high
agent: plan
web: false
action: suggest
---
Look for injection, missing authorization checks and secrets in logs.
```

必須なのは `name` と本文だけです。`model` がなければ、レンズはセッションの既定値を使います。`action` は `suggest`、`todo`、`session`、`worktree`、`draft-pr` のいずれかです。

リポジトリのレンズはレンズ一覧に表示されますが、自分のマシンでチェックを入れるまで実行されません。あとでファイルが変更されると、もう一度チェックするまで待機します。

## 通知とスキャンセッション

スキャンが提案を追加すると、OpenChamber が[通知](/ja/notifications/)します。**スキャン後**でオフにしている場合は通知されません。スキャンセッションはスキャン終了時にアーカイブされ、サイドバーには表示されません。受信トレイの**前回のスキャン**から開けます。

## 利用できる環境

受信トレイとスキャンは、Web アプリとデスクトップアプリで使えます。スマートフォンでは、受信トレイを開き、スキャンを開始し、提案に対応できます。設定はコンピューターから行ってください。VS Code 拡張機能ではタスクの提案を利用できません。
