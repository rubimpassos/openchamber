# スタックされたプルリクエスト

スタックとは、各 PR が下の PR の上に積み重なったプルリクエストのチェーンです。2 番目の PR のベースブランチは 1 番目の PR のブランチで、以降も同様です。大きな変更をこの形で分けると、各 PR がレビューしやすい小ささに収まります。OpenChamber は、スタックに属する PR が表示される場所すべてでスタック全体を表示し、チェーンの順序を保つ手助けをします。

スタックは GitHub で使えます。GitHub 自身がスタック（ネイティブのスタックされたプルリクエスト）を認識している場合、OpenChamber は GitHub のスタックを読み取ります。そうでない場合は PR のベースブランチからチェーンを見つけます。これはフォークや GitHub Enterprise Server にも対応します。

## スタックを見る

スタックに属するプルリクエストを、[Issues と PR](/ja/issues-and-prs/) ボード、プルリクエストビュー、または **Git** ビューで開きます。プレビューには **Pull request stack** セクションがあり、すべての PR を下から上へ一覧表示します。各行には PR の状態、チェック、コンフリクトの有無が表示され、いま見ている PR には印が付きます。読み取れない行は、色を表示する代わりにその旨を示します。

ボードの一覧では、スタックされた PR にスタック内の位置を示す小さなバッジ（**2/3** など）が付きます。スタック内の行をクリックすると、その PR が開きます。

行には警告が出ることもあります。

- **Behind base by N commits**: 下の PR が変更されたため、この PR は restack が必要です。
- **Base was merged. Retarget to main.**: 下の PR がマージされましたが、この PR はまだ古いブランチを指しています。
- **Still carries the commits of merged #N**: 下の PR が squash でトランクに取り込まれましたが、この PR にはまだその古いコミットが残っています。

## 別の PR の上に PR を作る

1. 一番上の PR のブランチを起点にして、新しい PR 用のブランチをチェックアウトします。
2. **Git** ビューの作成フォームを開きます。ブランチが開いている PR の上にある場合、フォームはその PR のブランチをベースに選び、**Stacked on #N** と表示します。**Use main**(デフォルトブランチ)で元に戻せます。スタックセクションの **Open stacked PR on top** でも同じフォームが開きます。
3. タイトルと説明を書いて PR を作成します。

GitHub.com では、OpenChamber は新しい PR を GitHub 自身のスタックにも登録します。GitHub が拒否した場合（フォークや古いサーバーなど）でも PR は作成され、スタックは引き続き表示されます。

## 下の変更後に restack する

スタックの下のほうの PR に新しいコミットが入ると、その上の PR は古くなります。**Fetch and restack** をクリックしてください。OpenChamber はリモートを fetch し、各ブランチを下のブランチの上に順番にリベースして、動いたブランチを push します。その間に他の誰かがブランチへ push していた場合、push は拒否されるので、作業が上書きされることはありません。

動くのは各ブランチ自身のコミットだけです。下で squash マージが行われたあとは、マージ済み PR の古いコミットは含まれません。

### restack でコンフリクトが起きたとき

restack は、コンフリクトした PR で止まります。それより下のブランチは restack 済みのまま、上のブランチは待機します。その後の動作は **Settings → Integrations → GitHub → Restack conflicts** によって決まります。

- **Pause and let me choose**（デフォルト）: スタックセクションが示すフォルダーでコンフリクトを解決し、ファイルをステージして **Continue** をクリックします。**Abort** はそのブランチを元の状態に戻し、残りをスキップします。**Ask the session to resolve** はコンフリクトを現在のセッションに渡します。
- **Let the session resolve it**: コンフリクトはそのままセッションに渡されます。セッションのターンが未解決なしで終わると、restack は自動的に続行します。

## スタックをマージする

下から順にマージします。スタックセクションに **Merge bottom PR #N** が表示されるのは、最も下の開いている PR だけで、いつものマージ方法が使われます。マージされると次の PR がトランクに移り、**Fetch and restack** でマージ済みのコミットが取り除かれます。そのあと次の PR をマージします。

## セッションでスタック全体を扱う

- スタックセクションの **Attach whole stack** は、各 PR の差分、チェック、コメントを、順序とブランチの概要とともにメッセージ欄に添付します。読み取れない PR があっても他は添付され、どれが失敗したかが通知されます。
- セッションの **Context sources** で、リンクした PR の **Follow whole stack** をオンにします。以後、セッションはスタックの変化に追従します。上に追加された PR、マージ、ターゲット変更は、リンクし直さなくても反映されます。このボタンはスタックに属する PR にだけ表示されます。

## 対応環境

スタックは Web アプリ、デスクトップアプリ、モバイルアプリで使えます。VS Code 拡張機能ではスタックは表示されません。
