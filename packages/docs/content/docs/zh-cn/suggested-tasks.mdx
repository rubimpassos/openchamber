# 建议任务

建议任务是读取项目并提出工作的扫描：被遗忘的 TODO、安全漏洞、与代码不再相符的文档。每条建议都会进入收件箱，你可以在那里基于它开始会话，把它变成待办或 issue，推迟，或忽略。从会话侧边栏顶部的灯泡图标打开收件箱；灯泡上有圆点表示有未处理的建议。

扫描只读取文件。它不能编辑文件、运行命令，也不能使用你的 MCP 工具。只有在你批准某条建议，或让某个视角自行行动时，工作才会开始。

## 为项目启用

1. 打开**设置 → 项目**，选择项目，然后打开**建议任务**标签页。
2. 勾选**扫描此项目以获取建议任务**。
3. 在**视角**下点击**添加视角**，选一个起点，例如**安全**或**被遗忘的 TODO 和 FIXME**。需要的话再添加第二个。
4. 选择**何时扫描**。**手动**只在你自己启动时运行扫描。
5. 点击**立即扫描**。

收件箱会显示扫描正在运行。每个视角完成后会添加它的建议，通常在几分钟内。

## 视角

一个视角寻找一类工作。每个视角包含：

- 名称，以及说明要找什么的提示词
- 自己的模型、思考级别和代理，或使用项目的会话默认值
- 网络访问，除非你允许，否则关闭；依赖项视角用它来检查当前版本
- 对发现结果的处理方式

起点有：被遗忘的 TODO 和 FIXME、安全、性能、无障碍、测试覆盖率、过时的依赖项、过时的文档和死代码。每个起点都会把它的提示词复制到你的视角中，所以你可以修改。**自定义视角**从空白开始。

一次扫描中的每个视角都在各自的会话中运行。其中一个失败时，其他视角仍会添加它们的建议，收件箱会说明哪个视角失败以及原因。点击视角旁边的播放按钮，可以只用该视角扫描。

### 视角如何处理它的建议

默认情况下，视角只提出建议：所有内容都在收件箱中等待。你也可以让它自行行动：

| 选项 | 每条新建议的处理 |
|---|---|
| 仅建议 | 在收件箱中等待。 |
| 添加到项目待办 | 成为[项目笔记、待办与计划](/zh-cn/notes-todos-plans/)中的一个待办。 |
| 开始会话 | 项目中的一个会话开始处理它。 |
| 在新工作树中开始会话 | 它会获得自己的 [worktree](/zh-cn/worktrees/) 和会话。 |
| 工作直到生成草稿 PR | 一个 worktree 会话把它当作[目标](/zh-cn/session-goals/)来处理，并打开草稿 PR。 |

后三项会在不询问的情况下开始会话，这些会话会消耗 token。

## 扫描何时运行

- **手动**：仅在你点击**立即扫描**时
- **每天**或**每周**：在你选定的时间和时区
- **Cron 计划**：任意 cron 表达式，例如 `0 9 * * 1-5` 表示工作日 9:00

**静默时段**会跳过落在某个时段内的计划扫描，例如 22:00 到 07:00。你自己启动的扫描始终会运行。扫描的时间由与[计划任务](/zh-cn/scheduled-tasks/)相同的调度器安排，所以只要 OpenChamber 服务器在运行，即使窗口已关闭，扫描也会运行。

## 扫描查看什么

- **仅这些文件**和**跳过这些文件**每行接受一个模式，例如 `src/**` 或 `*.test.ts`。
- **分支**会在临时副本中扫描另一个分支，之后副本会被删除。留空则按原样扫描项目文件夹。
- **只查看自上次扫描以来更改的文件**会让之后的扫描只读取有变化的部分。范围内没有变化时，扫描会被跳过，不产生任何费用。

## 限制

- **每次扫描的建议数**限制一次扫描在所有视角中添加的数量。会保留最严重、最确定的建议。
- **达到令牌预算后停止扫描**会在扫描用掉这么多 token 后，停止所有仍在读取的视角。
- **最低置信度**和**最低严重程度**会排除低于该级别的建议。

## 收件箱

每条建议会显示标题、为什么重要、涉及的文件和行、发现它的视角、严重程度，以及视角有多确定。点击文件会在对应行打开它。

- **开始会话**会在项目中以该建议作为提示词开始一个会话。
- **批准为**提供更多处理方式：
  - 在新工作树中开始会话
  - 工作到草稿 PR的 worktree 会话
  - 先由你编辑的新草稿，在这里也可以选择隔离空间
  - 项目待办
  - GitHub、GitLab 或 Linear 上的 issue
- **推迟**会将其隐藏一天、一周或一个月。
- **忽略**会询问一个可选的原因。

创建 issue 会打开跟踪器的新建 issue 页面，并填好标题和描述。你用自己的账号提交。

## 告诉扫描你不想要什么

扫描会把发现的内容与已处于未处理、已推迟或已批准状态的建议比较，并略过相似的内容。扫描还会与项目所绑定的 GitHub 或 GitLab 仓库以及已映射的 Linear 团队中未关闭的 issue 比较。如果某个提供方出错，或待办列表超过 10 页，扫描会显示警告。相似度匹配可能漏掉措辞不同的重复项。默认情况下，它们还会读取你忽略过的建议及其原因，以及你未完成的项目待办，所以在某条建议上写“我们接受这个风险”，就能让类似的建议不再出现。两者都可以在**避免重复**下关闭。

## 仓库中的视角

团队可以把视角作为 markdown 文件放在 `.agents/lenses/` 中共享：

```markdown
---
name: Security review
model: anthropic/claude-sonnet-4-5
variant: high
agent: plan
web: false
action: suggest
---
Look for injection, missing authorization checks and secrets in logs.
```

只有 `name` 和正文是必需的。没有 `model` 时，视角使用会话默认值。`action` 是 `suggest`、`todo`、`session`、`worktree` 和 `draft-pr` 之一。

仓库中的视角会出现在视角列表里，但只有在你于自己的机器上勾选后才会运行。如果之后有人修改了该文件，它会等你重新勾选。

## 通知与扫描会话

扫描添加建议后，OpenChamber 会[通知](/zh-cn/notifications/)你，除非你在**扫描之后**下关闭了它。扫描会话在扫描结束时归档，因此不会出现在侧边栏中。从收件箱的**上次扫描**下可以打开其中一个。

## 在哪里可用

收件箱和扫描可在 Web 应用和桌面应用中使用。在手机上，你可以打开收件箱、启动扫描并处理建议；设置请在电脑上完成。VS Code 扩展不提供建议任务。
